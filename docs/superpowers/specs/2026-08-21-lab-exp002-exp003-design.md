## 2. EXP-002 tonight's tides — 仪器设计

**定位:** 受试者仍是那个深夜刷手机的人,但这次带着一个具体问题来,不是来陪伴一段过程的。EXP-001 是**过程性仪器**(呼吸,需要你跟着它度过几分钟);EXP-002 是**查询性仪器**(潮汐表,你问它一个问题,它给你几个数字,你就走)。这个身份差异决定了它不需要 EXP-001 那种"沿会话递减"的时间纵深——它是一次性读数,不是一段陪伴。

**反默认:** 默认版本是睡眠计算器 App 的长相——整洁折线图、X/Y 轴、图例"Cycle 1/2/3/4/5"、原生 `<input type="time">`。这一整套"仪表盘感"正是 DESIGN §10.1 明确否决的语言(全站没有 dashboard 组件),原生 time input 的浏览器 UI 铬更是直接击穿"无第二种彩色、无 chrome 泄漏"的纪律(§DESIGN 2)。

**签名:** 潮汐用与 EXP-001 同源的 simplex-noise 场画法(视觉上的"仪器亲缘性"——访客能认出这是同一栋楼的仪器),但参数化方式完全不同、不可互换:振幅按**真实睡眠结构**走——第一个周期深睡占比最高,之后逐周期变浅、REM 占比上升(简化但不失真的模型),不是 EXP-001 那种对称呼吸升降。周期边界处的"浅睡窗口"用全站唯一强调色的短区间高亮 + mono 时间读数标出——那是这件仪器"报数"的地方,其余的场只负责"看起来是潮汐"。

**输入机制(就寝时间):** 不用原生 time input(理由见反默认)。改成 mono 大字读数本身即控件:`bedtime · 23:30`,数字可用 ↑↓ 微调分钟、点击后可直接键入两位数覆盖,`:focus-visible` 用全站统一绿环。**默认值 = 访客此刻的本地时间**("如果现在上床"),不是空表单——呼应 HOME §4.6 建立的"仪器随时汇报真实状态"的身份,而不是等待填空的问卷。

**潮汐范围与窗口:** 从 bedtime 起横向铺开到 +9h(覆盖 5–6 个周期),不做无限滚动。入睡缓冲取 +14min(常见简化模型),此后每 90 分钟一个周期边界。**浅睡窗口是一段区间(边界 ±10min 的绿色高亮),不是一个精确点**——真实生理不会精确到分钟,给一个假装精确的单点比给一个诚实的区间更不专业。每个窗口旁一行 mono 候选醒来时间。

**诚实条款(不许假,本实验的核心纪律):** 记录面板 observation 栏必须写明:这是基于人群平均 90 分钟周期的**启发式模型**,不是这位访客的个人睡眠实测数据;真实周期时长因人而异、因夜而异(压力、酒精、时差都会改变它)。这句话直接对应 SOUND-DESIGN 里 noise floor 的"this instrument sleeps when the screen does"同款条款——是全站"不许假"红线在这件仪器上的落地,不是免责声明式的法务文字。

**声音:** 静音(§SOUND-DESIGN 4 已定,声化列候补,不进本期)。

**动效与降级:** 潮汐纹理保持缓慢漂移(与走廊 Wavy 同一手法基因、不同组件)——漂移代表"潮水没有停",是仪器仍在运行的证词,不是纯装饰。reduced-motion 降级为静态帧(取"如果现在上床"这个默认 bedtime 渲染的那一版,不做动画)。

**策展三问:**

1. **它在研究一个问题吗?** 今晚几点醒,最不难受?——是问句。
2. **拿走借来的组件,还剩下我的东西吗?** 拿走 simplex-noise 与场绘制手法,剩下:90 分钟睡眠结构的参数化方式(深浅比例逐周期变化,不是平坦重复)、浅睡窗口的区间表示法(非单点)、诚实条款本身。
3. **它的动画在传达信息吗?** 漂移=潮汐持续流动;高亮区间的位置与宽度=浅睡窗口,不是装饰。

### 实现路线

`<canvas>` 渲染,复用 EXP-001 已验证的 simplex-noise 场绘制手法(同一技术,不同参数化与不同的时钟——这里是"睡眠结构时钟"不是"4-7-8 呼吸时钟"),外加一层 DOM 覆盖层承载 bedtime 读数控件与醒来时间标签(mono,不进 canvas 绘制,保证可选中、可被屏幕阅读器读到)。bedtime 状态是本组件唯一的 state,变化时重算窗口数组,不需要动画过渡(即时重绘即可,变化频率低,不值得为它做过渡动画预算)。

## 3. EXP-003 dream decay — 仪器设计

**定位:** 首发三件里唯一一件"访客提供数据、仪器随时间改写数据"的实验——EXP-001/002 都是访客**读**仪器,EXP-003 是仪器**用**访客:它需要访客的一段梦作燃料,然后开始遗忘它。这个反转本身就是"反转 EncryptedText"这个设计动作的字面意思:EncryptedText 是乱码→清晰(解密),dream decay 是清晰→乱码(遗忘)。

**反默认:** 默认版本是"打字机效果留言板"——输入文字、炫酷动画展示、存起来、访客离开,谁也不会再关心它。这没有回答任何问题。真正的问题(梦是在哪一次复述里丢掉的)要求"遗忘"必须是**真实发生、不可逆、由复访本身触发**的一件事,而不是一个可以无限重播的特效循环。

**机制:** 用 Placeholders And Vanish Input(`docs/COMPONENT-SOURCES.md` 已为本实验预留)让访客写一段梦,提交后**仅存本地 `localStorage`**(不上传、不联网——静态站物理上也做不到)。**每次重新打开这个实验页就是一次"复述"**:如果本地已有一份梦,mount 时自动触发一次衰减——随机选中一部分词(约 15%,不低于下限)替换为乱码字符或直接消失,存回新版本,并用类 EncryptedText 的字符抖动动画把旧文字"演变"为新的衰减版本(变化要能被看见,呼应策展三问③,不是无声跳变)。**衰减有下限:不低于原文 20% 的词,且首句保留一个锚点词**——模拟"遗忘留碎片,不会瞬间清零"这一更诚实的模型(结构上与 EXP-001"基线递减、下限 0.18"遥相呼应,但不是刻意对称——两者都在回答"这件仪器会不会真的归零"这同一类诚实问题)。

**一个我替你做了的判断,写在这里请你确认:** 触发方式我选了"**打开即算一次复述**",没有做成"点一个『重读』按钮才衰减"。理由:遗忘不是访客能主动选择要不要发生的事——如果做成按钮,访客可以选择永不点击来保存记忆,那这件仪器研究的问题就不成立了(它变成了"一个可以被叫停的遗忘",不诚实)。代价是:访客单纯想回来看看这段梦,一看就真的又丢了一点——这是设计意图,不是 bug,但这个机制不可逆,值得你在我写 plan 之前点头。首次写入时面板会提前把这件事说清楚(不许假红线:不能让访客在不知情的情况下"被遗忘背刺"),但机制本身我没有做成可选项。**如果你想要一个更温和的版本(比如手动重读按钮),告诉我,这一条比较容易改。**

**另一个待确认:字体。** DESIGN §2 规定 Lora 只出现在"走廊 h1 与长文正文"两处;梦境文字虽然是"被写下的东西",直觉上很像"被阅读的东西",但按这条硬规则不该是第三个例外,我把它归为 Geist Sans(与其它 /lab 卡片文字同级)。如果你想为这一件破例给 Lora,告诉我就改——这条规则本身就是全站字体纪律里唯一可能有争议的边界情况。

**隐私(设计的一部分,不只是技术事实):** 这段梦只存在访客自己浏览器的 localStorage 里,不会发送到任何服务器。面板文案会明确写这句话——这是对"这可能是一个会被写下真心话的输入框"的礼貌,呼应全站 PII 纪律(§ABOUT-DESIGN 1)的精神,即便这次不涉及本人信息。

**声音:** SOUND-DESIGN §4 已明确"静音,且是内容"——遗忘本身不发出声音,这句话要原样出现在记录面板 observation 栏,不是留白。

**策展三问:**

1. **它在研究一个问题吗?** 梦是在哪一次复述里丢掉的?——是问句,且需要多次复访才能亲眼验证,天然不是一次性演示。
2. **拿走借来的组件,还剩下我的东西吗?** 拿走 vanish input 与字符抖动手法,剩下:衰减算法本身(选词方式、下限、锚点保留)、"复访即代价"的机制设计、localStorage-only 的诚实条款与隐私姿态。
3. **它的动画在传达信息吗?** 字符抖动动画显示的正是"哪些词刚刚丢了"——是测量的可视化,不是装饰。

### 实现路线

纯 DOM(不用 canvas——这是文字实验,不是场):vanish input 走已选型的 Aceternity 组件手法;衰减渲染复用 `components/ui/encrypted-text.tsx` 的字符抖动技术但反向驱动(目标态是"更乱"而不是"更清晰")。状态机很简单:`empty → written → decaying(N)`,N 是已复述次数,存在 localStorage 里的是当前文字快照本身(不需要另存原文,衰减是有损单向的,这也是设计的一部分)。

## 5. 无障碍与降级

- reduced-motion:EXP-002 canvas 降为静态帧(默认 bedtime 那一版);EXP-003 的字符抖动动画降为瞬时替换(衰减结果照常生效,只是不演过程)。

- 两者都不使用声音,不受 §SOUND-DESIGN 无障碍条款约束之外的新增义务。
- 仪表读数一致性:两实验的 mono 读数与其它房间并排截图应分不出出处(§DESIGN 2)。
